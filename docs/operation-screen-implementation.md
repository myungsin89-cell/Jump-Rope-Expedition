# 현황 중심 운영 화면 · 1차 구현 결과

> 2026-10-20 · 로컬 운영 UI와 연습 기록 연결 완료  
> 기획 기준: `operation-flow-reorganization.md`, 결정 로그 D-021·D-022  
> 공식 인증·보상·훈장 수여 기능은 이번 단계에 포함하지 않음

이 문서는 1차 화면 개편 결과다. 이후 D-023의 로컬 우선 결정으로 훈장 관리·연습 수여·+10P 장부·아이콘·개인 이력을 연결했다. 최신 기능 상태는 `local-feature-progress.md`를 기준으로 하며 아래의 훈장 미구현 설명은 당시 상태를 뜻한다.

## 1. 실제로 연결한 흐름

**표지의 원정 시작하기 → 원정 목록 → 원정 선택 → 현황판**

- 새 원정/이어가기 중간 선택창을 제거했다.
- 기존 저장 원정은 목록 카드로 표시하고, 원정 만들기에서 전체 학생 명단만 먼저 등록한다.
- 별도 작명은 필수가 아니다. 목록에서 구분할 표시 이름은 선택 사항이며 기존 저장 이름은 보존한다.
- 원정 안의 상위 메뉴는 현황·명단·시즌 설정 세 개다.
- 현황의 경기 기록하기에서 준비된 현재 기록 시즌의 개수 입력으로 바로 연결한다.
- 기록 저장 후 현황으로 돌아가 원정대별 최근 순위와 연습 획득 합계를 확인한다.

## 2. 현황판

- 현재 선택한 기록 시즌·기간·기록 수·원정대 수·학생 수
- 원정대별 번호·이름·번호순 전체 명단, 이름 옆 원정대장 표시와 도전점퍼 테두리
- 최근 연습 순위와 해당 시즌의 연습 획득 합계
- 저장한 연습 기록과 당시 이름·원기록·개인 실제 기록
- 대원 이름을 누르면 학생 상세 모달에서 이름 수정·도전점퍼 지정·배수 조회 및 변경·개인 기록 확인

현재 실제 시즌 시작·종료는 연결 전이다. 따라서 날짜가 지났다는 이유로 자동 진행·종료하지 않는다. 화면 상태는 `시즌 설정 필요`, `대원 구성 필요`, `기록 가능 · 연습`으로 구분한다.

**연습 획득 합계는 공식 포인트 잔액이 아니며 구매에 사용할 수 없다.** 공식 잔액·누적 승점·훈장 데이터가 없는 자리에 가짜 숫자를 넣지 않는다. 다른 원정대의 전략을 숨기는 학생용 화면도 아직 연결하지 않았다.

## 3. 30명 명단과 모달

- 현황과 명단은 공통 번호순 목록을 사용하고 원정대별로 나란히 보여 준다. 개별 학생 카드나 이름 칩을 반복하지 않는다.
- 미배정 학생은 별도 구역에 표시한다. 원정대의 `대원 편성` 모달에서 여러 명을 함께 선택한다. 현재 대원은 미리 선택되어 있고 다른 학생의 기존 소속도 보인다.
- 선택 해제한 기존 대원은 미배정으로 옮기며, 다른 원정대 학생을 고르면 해당 소속에서 이동한다. 두 동작은 한 번에 저장하고 이동 전 영향과 인원을 안내한다.
- 이름 입력칸을 30개 상시 표시하지 않는다. 이름을 선택해 상세 모달에서 수정한다.
- 학생 추가 버튼은 별도 모달을 열며 여러 줄 붙여넣기와 동명이인 등록을 지원한다.
- 각 원정대의 이름·대장 설정 버튼에서 설정 모달을 연다. 대장 지정은 추가 권한을 만들지 않는다.
- 소속 원정대를 변경하면 이전 원정대의 대장·도전점퍼 지정을 함께 정리한다.
- 원정대별 도전점퍼는 1~2명이며 개인 배수는 각각 1~3배다. 지정과 배수 변경은 학생 상세에서만 하며 현황·명단에는 배수를 노출하지 않는다.
- 도전점퍼 줄은 전체 테두리와 짧은 도전 표시로 구분한다. 원정대장과 도전점퍼 역할이 겹쳐도 같은 이름을 여러 구역에 반복하지 않는다.
- 저장 실패 시 모달을 닫지 않고 입력을 유지한다. 재시도 시 학생을 중복 추가하지 않는다.
- 모달은 네이티브 dialog를 사용해 포커스를 제한하며 닫으면 원래 버튼으로 돌아간다. 미저장 이름·학생 입력·도전점퍼 설정·편성 선택은 닫기 전에 확인한다.
- 편성 모달은 긴 선택 명단만 내부 스크롤하며 인원과 저장 동작을 별도로 유지한다. 학생 상세의 훈장·성장 기록은 접어서 시작하고 실제 기록이 있으면 성장 기록을 펼친다.

## 4. 2~4개 원정대

- 기록 전 원정대 수를 2·3·4개 중 정할 수 있다.
- 줄이는 원정대의 학생은 삭제하지 않고 미배정 상태로 남긴다.
- 기존 학생 ID·훈장/개인 기록 연결용 정체성을 변경하지 않는다.
- 작성한 개수나 저장 이력이 있으면 원정대 수 변경을 잠근다. 기록을 지워 변경하는 우회 동작은 제공하지 않는다.
- 기록판·저장·순위 계산은 2~4개를 처리한다.
- 4위 순위 보너스는 미정이므로 `null`로 유지하고 `미정`으로 표시한다. 0P 등 임의의 숫자로 대체하지 않는다.
- 4위가 포함된 연습의 해당 원정대 획득 합계도 `일부 미정`으로 표시한다. NaN이나 임의 합계를 저장하지 않는다.
- 영웅 엔진은 아직 없으므로 2팀 영웅 비활성화를 구현했다고 보고하지 않는다.

## 5. 데이터와 원본 보존

기존 키를 유지한다.

- 명단 작성 중: `jre.preparation.draft.v2`
- 저장 원정: `jre.preparations.v2`
- 연습 기록: `jre.practice-matches.v1.<원정 ID>`

기존 `className` 내부 필드는 호환을 위해 유지하고 화면에서는 원정 표시 이름으로 쓴다. 원정대의 선택적 `captainId`, 원정의 선택적 `currentSeasonIndex`를 추가했다. 필드가 없는 기존 3팀 저장 자료도 그대로 읽는다.

개수가 입력된 연습 기록은 당시 명단·도전점퍼·배수 스냅샷을 유지한다. 준비 메뉴의 변경으로 기존 개인 개수를 다른 학생에게 재귀속하지 않는다. 아직 비어 있는 기록판은 최신 구성을 가져온다.

시즌별 합계는 분리하지만 기존 원기록 성장 비교 규칙을 바꾸지 않는다. 시즌 순서 변경·개수 축소로 기록의 시즌 연결이 바뀌지 않도록 작성·저장 기록이 있는 시즌을 보호한다.

## 6. 코드 위치와 이전 코드

- `src/features/expedition/`: 현황·명단·학생 상세·모달·운영 도우미·전용 스타일
- `src/features/preparation/PreparationWorkspace.tsx`: 원정 생성·목록과 기존 저장 자료 읽기
- `src/features/preparation/SeasonSettings.tsx`: 재사용하는 시즌 편집기
- `src/features/matches/`: 연습 기록판과 2~4개 입력 스냅샷
- `src/shared/domain/matchScoring.ts`: 순위·예상 포인트 계산, 4위 미정 처리

이전 단계형 UI의 `GamePreparationBoard.tsx`, `RosterSettings.tsx`, `JumperSettings.tsx`는 활성 코드에서 제거하고 원본과 해시가 같은 사본을 `artifacts/archive-preparation-ui-20261020/`에 보관했다. 필요하면 복구할 수 있다. 원래 명단·기록·이미지·오디오나 다른 담당자의 카드 UI는 삭제하지 않았다.

## 7. 검증

- 단위 테스트 61개 통과: 기존 호환·동명이인·대장 이동·일괄 편성의 역할 보존/정리·원정대 수·도전점퍼·성장·4위 미정 등. 별도 담당자의 보스 카드 검증 포함
- 운영 화면 브라우저 테스트 13개 통과: 테두리 균일성·배수 상세 전용 노출·편성 이동/취소/저장 실패 재시도·도전점퍼 상한 검증 추가. 독립 병력·영웅·보스 카드 미리보기는 별도 담당자의 테스트로 분리
- 최종 전체 회귀 19개 통과: 운영 13개 + 독립 카드 미리보기 6개. 기존 기록용 테스트 픽스처도 화면 준비를 기다린 후 이동하도록 안정화
- 타입 검사·프로덕션 빌드 통과
- 수정 범위 ESLint 통과
- 375×812, 812×375, 768×1024, 1440×900에서 운영 메뉴 가로 넘침 없음
- 저장 실패 후 모달 재시도·중복 방지·새로고침 복구 검증

검증 이미지는 `artifacts/operation-*.png`로 남긴다. 표지에서 시작하는 실제 검증은 `tests/e2e/startup.spec.ts`, 운영 동선은 `preparation.spec.ts`와 `preparation-flow.spec.ts`를 따른다. 과거 준비 UI용 수동 캡처 스크립트는 현행 동선의 검증 기준이 아니다.

## 8. 다음 단계

1. 교사 인증·서버 장부를 전제로 커스텀 훈장 정의와 경기 독립 수여를 연결한다.
2. 수여 한 건당 원정대 +10P를 서버에서 한 번만 반영하고 현황 아이콘·학생 상세·서로 다른 수상자 누적을 연결한다.
3. 4위 보너스·4팀의 역전 조건·진행 중 원정대 수 변경·귀속 시즌 없는 훈장의 미정 정책은 해당 구현 전에 확인한다.
4. 공식 시즌 시작/종료·잔액·승점·팀 QR는 별도 구현한다.

현재 훈장 수여 버튼이나 가짜 포인트 지급을 임시로 만들지 않았다. 학생 상세에는 아직 연결 전임을 표시한다.
