# 공식 경기 기록판 구현 범위

> 2026-10-21 · 기존 연습 입력 흐름을 교사 인증 기반 공식 확정·포인트 지급·취소 감사 장부로 전환했다. 기존 로컬 연습 기록과 저장 키는 보존한다.

## 현재 흐름

교사용 현황에서 원정대별 대원·기록할 시즌·도전점퍼가 준비되면 `경기 기록하기`를 누른다.

1. 명단에서 원정대별 도전점퍼 1~2명과 학생별 1·2·3배를 정한다.
2. 원정대 전체 원기록과 도전점퍼 실제 기록을 입력한다.
3. 순위 기록·공동 순위·확정 예정 포인트를 확인한다.
4. `경기 결과 확정하기`로 Supabase의 공식 경기와 포인트 원장에 저장한다.
5. 오입력은 3~200자의 사유를 남겨 취소한다. 원본을 삭제하지 않고 지급액과 같은 크기의 반대 거래를 추가한다.
6. 다음 경기는 새 ID로 입력하며, 취소되지 않은 직전 기록을 성장 비교에 사용한다.

## 계산 규칙

- 순위 기록 = 팀 원기록 + 개인 실제 기록 × (배수 - 1)의 합.
- 높은 기록부터 공동 순위를 적용하며 다음 순위를 건너뛴다.
- 참가 30P + 순위 30/20/10/0P + 원기록 향상 20P.
- 4위는 순위 보너스가 0P이며 참가 30P와 성장 보너스는 동일하게 적용한다.
- 첫 기록·동률·하락에는 성장 보너스가 없다. 배수는 성장 비교에 적용하지 않는다.
- 0은 유효한 값이며 빈칸·음수·소수·안전 범위를 벗어난 정수는 거절한다.
- 도전점퍼 개인 기록은 팀 원기록보다 클 수 없고, 같은 학생을 한 경기에서 중복 선택할 수 없다.

## 서버 장부와 안전장치

- `official_matches`: 교사·원정·경기 ID별 확정 payload와 확정/취소 상태를 보존한다.
- `team_point_ledger`: 원정대별 경기 지급과 취소 반대 거래를 append-only로 남긴다.
- 동일 경기 ID의 재요청은 중복 지급하지 않는다. 같은 ID로 다른 payload를 보내면 거절한다.
- 확정과 팀별 포인트 지급, 취소와 포인트 회수는 각각 하나의 PostgreSQL 트랜잭션에서 처리한다.
- RLS로 로그인한 교사는 자기 경기와 원장만 읽을 수 있고, 쓰기는 검증 RPC로만 허용한다.
- 입력 중인 draft는 기존 `jre.practice-matches.v1.<원정 ID>`에 자동 보관한다. 공식 상태도 교사 원정 스냅샷에 포함해 다른 기기에서 복원한다.
- 서버 확정 실패 시 입력값을 지우지 않는다. 서버 확정 후 스냅샷 동기화만 실패하면 현황의 `서버 저장`으로 재시도한다.

## 남은 결정

- 공식 누적 승점과 시즌 종료 규칙.
- 학생 기기에서의 직접 경기 입력 권한은 제공하지 않는다.
