# 경기 기록판 구현 범위

> 현황판 직접 진입과 2~4개 원정대의 연습 입력·순위·저장을 연결했다. 전체 개편 결과는 `operation-screen-implementation.md`, 목표는 `operation-flow-reorganization.md`를 따른다. 경기 독립 훈장 수여와 공식 보상은 아직 연결 전이다.

## 현재 흐름

교사용 현황에서 원정대별 대원·기록할 시즌 하나·도전점퍼가 준비되면 `경기 기록하기`를 누른다. 확인 버튼 이력이나 미작성 미래 시즌은 진입을 막지 않는다.

1. 명단에서 원정대별 도전점퍼 1명 또는 2명과 학생별 1·2·3배를 미리 정한다.
2. 새 기록판은 이 지정을 가져와 바로 설정한 2~4개 원정대의 원기록과 도전점퍼 실제 기록을 입력한다. 준비된 시즌만 선택할 수 있다.
3. 순위 기록·공동 순위·예상 포인트를 확인한다.
4. 연습 기록을 저장하거나 개수를 다시 확인한다.
5. 다음 연습 기록은 새 입력으로 만들며, 직전 저장한 연습 원기록을 성장 비교에 사용한다.
6. 저장 후 `현황으로 돌아가기`에서 최근 순위·해당 시즌의 연습 획득 합계·기록 이력을 확인한다.

시간·경기 총수·수업 세부 규칙은 입력받지 않는다. 도전점퍼를 다시 정할 때 기존 개수는 유지하되,
담당 학생을 바꾸면 그 칸의 개인 기록을 비워 다른 학생에게 잘못 귀속되지 않도록 한다.

## 확정 규칙을 적용한 계산

- 순위 기록 = 팀 원기록 + 개인 실제 기록 × (배수 - 1)의 합
- 높은 기록부터 공동 순위를 적용하며 다음 순위를 건너뛴다.
- 참가 30P + 순위 30/20/10P + 원기록 향상 20P를 예상값으로 계산한다.
- 4위 순위 보너스는 미정이므로 예상 합계도 `null`로 두고 화면에 미정으로 표시한다. 이를 0P로 대체하지 않는다.
- 첫 기록·동률·하락에는 성장 보너스가 없다. 성장 비교에 배수를 적용하지 않는다.
- 0은 유효한 개수이고 빈칸을 0으로 처리하지 않는다.
- 숫자가 아닌 값·음수·소수·정수로 안전하게 계산할 수 없는 큰 값은 안내한다.
- 도전점퍼 개인 기록은 포함된 팀 원기록보다 클 수 없다.
- 같은 학생을 한 경기의 도전점퍼로 중복 선택하지 않는다.

## 연습과 운영 데이터의 구분

이 기록판은 서버 연동 전의 UI·입력 검토용이다. **공식 경기 확정이나 보상 지급을 하지 않는다.**

- 화면에 연습용 기록판과 예상 포인트임을 표시한다.
- 순위와 포인트는 저장하지 않고 입력 스냅샷에서 미리보기로 계산한다.
- `jre.practice-matches.v1.<학급 ID>`에 작성 중인 입력과 연습 기록만 저장한다.
- 팀 포인트 장부·구매·영웅·승점에 쓰지 않는다.
- 팀별 원기록, 학생 ID·이름, 개인 실제 기록, 배수와 입력 당시 팀 명단을 스냅샷으로 보관한다.
- 훈장 제작·수여를 아직 연결하지 않아 훈장 포인트는 계산에 포함하지 않는다. 최신 규칙의 수여당 +10P는 경기 합계가 아니라 별도의 수여 거래이며 추후 연결 때 중복 합산하지 않는다.
- 공식 성장 기준은 서버에 확정된 경기다. 현재 미리보기의 성장 기준은 직전 저장한 연습 기록이다.
- 팀 QR 세션이나 학생 접속 권한을 흉내 내는 접속 화면은 제공하지 않는다.

## 복구와 검증

- 새로고침 후 선택한 도전점퍼·배수·입력 중인 개수를 복구한다.
- 기존 개수가 있는 작성 중 기록은 당시 팀원·도전점퍼를 유지하고 안내한다. 준비 메뉴의 변경은 다음 새 기록에 적용한다.
- 개수를 아직 입력하지 않은 빈 기록판은 최신 준비 내용을 가져올 수 있다. 이전 형식의 연습 기록판에서 도전점퍼를 정하는 흐름도 복구용으로 유지한다.
- 저장된 연습 기록은 수정하지 않고 새 연습 기록을 추가한다.
- 같은 연습 ID의 재저장은 중복 추가하지 않는다.
- 저장 실패 시 화면 입력을 유지한다. 읽을 수 없는 원본을 초기화하거나 덮어쓰지 않는다.
- 메달·실제 시즌 시작/종료·정정·서버 보상 처리는 후속 구현 범위다.

공식 기록 확정은 교사 인증과 서버 트랜잭션·멱등성·감사 기록을 연결한 뒤 구현한다.
