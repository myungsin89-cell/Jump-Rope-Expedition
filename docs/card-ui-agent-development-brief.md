## 3. 필수 결과물

### A. 병력 카드 `UnitCard`

병력 4종을 같은 체계로 보여 주는 **읽기 전용** 카드입니다.

필수 표시:

- 기존 병력 그림: 얼굴·무기·날개가 잘리지 않게 표시
- 병력 이름
- 역할: 원거리 공격 / 근거리 공격 / 물리 방어 / 마법 방어
- 짧은 전투 설명
- 고정 가격 `30P`
- 선택적으로 전달받은 보유 수량. 전달하지 않으면 수량 영역을 숨김

이번에는 구매 버튼·장바구니·수량 증감·잔액·구매 확인창을 만들지 않습니다. 가격은 표시 정보일 뿐입니다. 수량을 전달받더라도 카드가 직접 변경하거나 저장하지 않습니다.

병력을 사는 것이 곧 자동 배치입니다. 별도의 편성 슬롯·출전 선택·장착 버튼을 만들지 마세요.

### B. 영웅 카드 `HeroCard`

공개된 영웅의 그림·등급·이름·전투 효과를 보여 주는 읽기 전용 카드입니다.

- 일반 / 희귀 / 전설을 색과 한글 등급명으로 함께 구분
- 카드 프레임은 이미지에 합성하지 않고 CSS·SVG로 표현
- 전투 효과가 주 정보입니다. 수집 희소성만 강조하지 않기
- 긴 효과 문구도 생략하지 않고 읽을 수 있게 줄바꿈
- 가격·뽑기 버튼·장착/해제·출전 선택은 없음
- 카드 공개나 획득을 실제 처리하는 애니메이션·사운드는 없음

**미공개 상태**도 같은 컴포넌트에서 지원하세요. 이때는 고정된 카드 뒷면과 `미공개 영웅`만 보여 줍니다. 클릭해서 뒤집는 기능은 만들지 않습니다.

## 5. 공개 범위는 디자인 상태와 분리하세요

영웅 공개 상태는 시각적 장식이 아니라 정보 공개 규칙입니다.

- 같은 팀의 미공개 카드: 고정된 카드 뒷면과 `미공개 영웅`만 표시
- 같은 팀의 공개된 카드: 이름·등급·효과 표시 가능
- 다른 팀: 최종 대전 전에는 카드 상세를 사용하지 않고 획득 사실·총 장수만 표시하는 것이 원칙. 이번 컴포넌트에서 다른 팀 보드를 만들지는 않음
- 개발용 전체 카드 미리보기: 샘플 카탈로그이며 실제 팀의 획득 정보와 연결하지 않음

미공개 카드의 props에는 실제 영웅 객체를 받지 않는 구분 타입을 권장합니다.

```ts
type HeroCardProps = { state: 'sealed' } | { state: 'revealed'; hero: HeroDefinition };
```

미공개 상태에 영웅 이름·ID·등급·효과·그림 경로를 CSS로 숨겨 넣지 마세요. `alt`, `title`, `aria-label`, `data-*`, 숨겨진 요소, DOM 주석에도 넣지 않습니다. 등급별 뒷면이나 색으로 결과를 추측하게 만들지 마세요.

공개된 캐릭터 카탈로그 자체와 실제 팀이 어떤 영웅을 획득했는지는 다른 정보입니다. 서버 권한 검증과 실제 배정 정보 보호는 메인 담당자가 연결할 범위입니다. 이 UI만으로 보안이 완성됐다고 보고하지 마세요.

## 6. 디자인과 읽기 편의

### 전체 방향

- 따뜻한 숲속 모험. 기존 일러스트가 주인공이고 프레임은 보조 역할
- 크림 아이보리 `#FBFBF9`, 딥 포레스트 그린 `#1B4332`, 민트 `#52B788`
- 이름·짧은 제목·등급에는 기존 `--font-display`의 주아 글꼴
- 효과 설명에는 기존 `--font-ui`를 사용하여 긴 문장 가독성 유지
- 기존 색·글꼴 변수를 읽어 사용하고 새 전역 변수를 덮어쓰지 않기
- 다른 앱의 폴더 캐릭터·슬로건·로그인 화면을 가져오지 않기

### 카드 표현

- 비대칭 모서리와 절제된 잉크 그림자
- 일반은 숲색, 희귀는 청록·푸른색, 전설은 금빛을 보조색으로 사용 가능
- 등급은 반드시 한글 텍스트를 병기. 색·별 개수만으로 구분하지 않기
- 기본 화면에서 움직이지 않는 카드로 완성. 상시 빛 번짐·입자·반짝임은 제외
- 이미지에는 `object-fit: contain`. 정해진 이미지 영역과 충분한 여백으로 전체 모습 보존
- 캐릭터 비율을 찌그러뜨리거나 얼굴·날개·무기를 확대 잘라내지 않기
- 이름·등급·설명은 이미지 안에 그리지 않고 HTML 텍스트로 유지
- 설명 길이가 달라도 겹치지 않으며 카드 높이를 억지로 고정해 텍스트를 숨기지 않기

### 반응형·접근성

- 375px 모바일에서 가로 스크롤이 생기지 않아야 함
- 작은 화면에서는 한 열로 편안하게 볼 수 있게 구성. 태블릿·PC는 공간에 맞게 격자 배치
- 필터 등 조작 버튼은 최소 44px, 주요 버튼은 56px 높이를 권장
- 필터는 실제 `button`과 `aria-pressed` 사용, 키보드·포커스 표시 제공
- 읽기 전용 카드 전체를 클릭 가능한 버튼처럼 꾸미지 않기
- 그림과 바로 옆 이름이 중복 낭독되지 않게 대체 텍스트를 정하기. 의미 없는 프레임·아이콘은 장식으로 처리
- 이미지 로드 실패 시 이름과 설명은 남기고 `이미지를 불러오지 못했어요` 대체 영역 표시
- 레이아웃 이동을 줄이도록 이미지 공간 예약. 화면 아래 이미지는 지연 로드 가능
- 기존 PNG는 수 MB급입니다. 별도 원본 편집·일괄 변환·새 이미지 생성은 하지 말고 크기와 성능 제약을 결과 문서에 기록
- 전환 효과를 넣는 경우 `prefers-reduced-motion`을 존중

## 7. 구현 구조와 연결 계약

다음 구조를 기준으로 하되, 작업 범위를 넓히지 않는 작은 파일 분리는 가능합니다.

```text
src/features/card-ui/
  types.ts                  # 카드 표시용 타입
  catalog.ts                # 확정 데이터와 기존 그림 import
  UnitCard.tsx              # 읽기 전용 병력 카드
  HeroCard.tsx              # 미공개/공개 영웅 카드
  CardPreview.tsx           # 개발용 전체 미리보기
  cards.css                 # 이 기능에만 적용되는 스타일
  preview-main.tsx          # 미리보기 전용 마운트
  index.ts                  # 메인 담당자가 사용할 공개 export
  catalog.test.ts
  cards.test.tsx
card-ui-preview.html
tests/e2e/card-ui.spec.ts
docs/card-ui-implementation.md
artifacts/card-ui/
```

### 컴포넌트 계약

- `UnitCard`: `unit: UnitDefinition`, 선택적 `ownedCount: number`
- `HeroCard`: 위의 미공개/공개 구분 타입
- `UnitDefinition`: `id`, `name`, `role`, `description`, `price: 30`, `imageSrc`
- `HeroDefinition`: `id`, `name`, `rarity`, `effect`, `imageSrc`
- 등급 데이터는 `common | rare | legendary`, 화면에서는 `일반 | 희귀 | 전설`
- 실제 팀의 학생 ID·잔액·서버 세션을 props나 샘플 데이터에 넣지 않기
- props를 수정하지 않기. 카드 내부에서 localStorage·Supabase·네트워크 요청을 사용하지 않기
- 외부에 노출할 export와 사용 예시를 결과 문서에 남기기

이미지는 Vite가 해석할 수 있는 정적 import로 연결하세요. 문자열로 미존재 공개 경로를 추측하거나 외부 이미지 URL로 대체하지 않습니다.

CSS는 `.jre-card-*` 같은 전용 접두사나 최상위 미리보기 클래스 아래로 한정하세요. `body`, `button`, `h2`, `img`, `:root`를 단독 전역 선택자로 수정하지 않습니다.

### 독립 미리보기 실행

`card-ui-preview.html`에서 `/src/features/card-ui/preview-main.tsx`를 불러오는 Vite 개발용 진입점을 만드세요. 미리보기 진입점에서 기존 `src/styles.css`를 읽어 가져오는 것은 허용하지만 파일 자체는 수정하지 않습니다.

```text
npm run dev -- --host 127.0.0.1 --port 4173
http://127.0.0.1:4173/card-ui-preview.html
```

이미 서버가 떠 있으면 해당 주소를 재사용하세요. 포트 충돌로 다른 주소가 열리면 실제 주소를 보고하고, 테스트 대상과 일치시키세요.

이 진입점은 개발 검토용입니다. 기존 빌드 설정은 수정하지 않으므로 기본 프로덕션 빌드에 별도 미리보기 HTML이 배포된다고 가정하지 않습니다. `npm run build` 성공만으로 카드가 실제 앱에 연결되었다고 보고하지 마세요.

## 8. 권장 작업 순서

1. 필독 자료와 실제 파일을 확인하고 담당 파일이 비어 있는지 점검
2. 확정 데이터·그림 경로를 중앙 카탈로그로 작성
3. 병력 카드 1개와 일반·희귀·전설 영웅 각 1개로 비율·텍스트·등급 차이를 먼저 맞춤
4. 같은 컴포넌트에 4종·15종 전체 데이터 적용
5. 미공개 상태, 이미지 오류 상태, 등급 필터 구현
6. 단위 테스트와 독립 미리보기 브라우저 테스트 작성
7. 데스크톱·모바일 화면을 실제로 열어 확인 후 이미지 저장
8. 수정 파일·실행 주소·검증 결과·남은 연결 작업을 결과 문서로 전달

중간 시안 확인을 위해 메인 App에 임시 연결하거나 기존 코드를 옮기지 마세요. 자율 판단 가능한 UI 작업은 끝까지 진행하고, 새 게임 규칙이나 작업 경계 변경만 질문해 주세요.

## 9. 검증 항목과 실행 명령

### 단위 테스트

- 병력 4종, 고유 ID, 가격 전부 30P, 그림 매핑 누락 없음
- 영웅 15종, 고유 ID, 일반 8·희귀 5·전설 2, 이름·효과·그림 매핑 일치
- 공개 카드에서 정확한 이름·등급·효과를 표시
- 미공개 카드의 DOM에 영웅 정체·등급·효과·그림 경로가 없음
- 수량을 넘기지 않으면 숨김, 0을 넘기면 0으로 표시, 전달받은 props를 변경하지 않음
- 이미지 오류 시 fallback을 표시해도 텍스트가 유지됨
- 미리보기 필터가 정확한 수의 카드만 보여 줌

### 브라우저 검증

- 미리보기의 병력 4개와 공개 영웅 15개, 미공개 예시가 정상 렌더링
- 실제 그림이 로드되고 404·관련 콘솔 오류가 없는지 확인
- 375×812, 812×375, 768×1024, 1440×900에서 화면 넘침·글자 잘림 확인
- 긴 효과를 가진 루미·레온의 설명과 일반·희귀·전설 프레임을 직접 확인
- 키보드 필터 조작과 포커스 표시, 모션 감소 설정 확인
- 검증 이미지는 `artifacts/card-ui/`에 저장하고 직접 열어 확인
- 메인 표지·준비·기록 화면에 CSS나 동작 영향이 없는지 기존 브라우저 테스트로 확인

```text
npm run typecheck
npm run test -- src/features/card-ui
npx eslint src/features/card-ui tests/e2e/card-ui.spec.ts
npm run build
npx playwright test tests/e2e/card-ui.spec.ts --project=chromium
npx playwright test --project=chromium
```

명령을 실제로 실행한 결과만 보고하세요. 기존 문제로 전체 검증이 실패하면 새 작업과 관계있는지 구분하고, 관련 없는 파일을 고쳐서 통과시키지 않습니다.

## 11. 후속 선택 작업 · 이번에는 진행하지 않음

카드 UI 인계 후 별도로 요청받으면 다음 중 하나를 맡을 수 있습니다.

- **교사용 빠른 사용 안내**: 최신 D-019 기준의 명단 → 팀 편성 → 이번 시즌 → 도전점퍼 → 기록 입력. 현재 제공하지 않는 교사 인증·팀 QR·공식 포인트를 가능한 것처럼 설명하지 않기
- **교사용 보스 선택 카드**: 기존 보스 5종 그림·이름·선택 상태만 props로 표시. 비밀 보스를 학생에게 공개하거나 시즌 설정 파일을 직접 수정하지 않기

두 작업의 파일 범위와 연결 계약은 착수 전에 따로 정합니다. 이번 요청에 묶어 범위를 넓히지 마세요.
