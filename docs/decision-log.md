# 줄넘기 원정대 결정 로그

> 갱신일: 2026-10-20
> 상태: 핵심 게임·운영 규칙 확정

이 문서는 대화에서 확정된 결정을 짧게 추적한다. 상세 구현 기준은 루트의 `줄넘기_원정대_개발_마스터_명세서_v1.0.md`를 따른다.

운영 화면 개편의 최신 정리는 `docs/operation-flow-reorganization.md`를 함께 본다. **D-021·D-022가 이전의 3팀 고정·준비 메뉴·경기 연결 훈장 규칙을 대체한다.** 문서에 정리된 목표와 현재 구현 완료 상태는 구분한다.

## D-001 · 운영 단위와 용어

- 상태: 확정
- `리그`라는 운영 단위를 없애고 **시즌**으로 통일한다.
- 한 원정은 교사가 정한 1~5시즌으로 구성하며, 그 안의 개별 팀을 원정대라고 부른다.
- `레이드`는 학생 화면에서 **최종 대전**으로 표시한다.
- 경기 순위 점수와 최종 대전 승점을 섞지 않는다.

## D-002 · 시즌과 보스

- 상태: 확정
- 교사가 시즌별 보스와 순서를 직접 정한다. 보스는 무작위 배정하지 않는다.
- 같은 원정에서 보스는 중복되지 않는다.
- 아직 시작하지 않은 시즌만 추가·삭제·순서 변경할 수 있다.
- 시즌이 시작되면 해당 보스는 변경할 수 없다.
- 교사는 보스만 선택하며 능력치와 상성은 수정하지 않는다.

## D-003 · 시즌 기간과 종료

- 상태: 확정
- 교사는 시작일과 종료 예정일만 설정한다.
- 경기 날짜·시간·총 경기 수는 고정하지 않는다.
- 종료 예정일에 자동 종료하지 않으며 교사가 버튼으로 종료한다.
- 종료 뒤 최종 대전 계산 전까지만 시즌 종료를 취소할 수 있다.
- 최종 대전 계산이 시작되면 시즌을 다시 열 수 없다.
- 확정 경기가 0개면 최종 대전 없이 시즌을 취소하며 시즌·보스를 소비하지 않는다.

## D-004 · 경기 입력 범위

- 상태: 확정
- 앱은 경기 시간과 줄넘기 세부 규칙을 정하지 않고 개수 입력판만 제공한다.
- 교사가 설정한 2~4개 원정대가 함께 경기할 수 있을 때만 진행한다. 일부 원정대만 임의로 제외해 순위를 계산하지 않는다.
- 중단된 경기는 입력·확정하지 않는다.
- 결석·장비 문제·재경기용 별도 상태를 만들지 않는다.
- 각 원정대와 교사 모두 기록을 입력할 수 있고 교사가 설정한 모든 원정대 기록을 최종 확정한다.
- 팀 제출 전 `팀원들과 기록을 확인했나요?` 안내를 표시한다.

## D-005 · 도전점퍼

- 상태: 확정
- 교사가 경기 시작 전에 팀별 도전점퍼 1명 또는 2명을 지정한다.
- 학생마다 1배·2배·3배 중 하나를 정하며 경기마다 바꿀 수 있다.
- 도전점퍼 개인 실제 기록을 별도로 저장한다.
- 팀 원기록에는 도전점퍼 기록이 이미 포함되고 순위 기록에는 추가 배수분만 더한다.
- `순위 기록 = 팀 원기록 + Σ(개인 실제 기록 × (배수 - 1))`이다.
- 팀과 개인 성장 판단에는 배수 적용 전 실제 기록만 사용한다.

## D-006 · 경기 순위와 팀 포인트

- 상태: 확정
- 모든 팀은 시즌마다 0P에서 시작하며 남은 포인트는 이월하지 않는다.
- 유효 경기 참가 30P를 참여 원정대 모두 받는다.
- 순위 보너스는 1위 +30P, 2위 +20P, 3위 +10P, 4위 +0P다.
- 공동 순위는 같은 높은 순위와 보너스를 받고 다음 순위를 건너뛴다.
- 현재 팀 원기록이 직전 확정 경기보다 높으면 성장 보너스 +20P를 받는다.
- 첫 경기, 같은 기록, 낮은 기록에는 성장 보너스가 없다.
- 훈장 1개 수여당 수여 당시 소속 원정대에 +10P를 지급한다. 경기 포인트와 별개의 수여 장부로 처리한다.
- 경기 순위로 승점을 지급하지 않는다.

## D-007 · 훈장 (기존 명칭: 메달)

- 상태: 확정
- 기본 훈장은 제공하지 않고 교사가 이름·설명·아이콘 또는 이미지를 직접 정한다.
- 만든 훈장과 학생의 수여 이력은 시즌이 바뀌어도 유지한다.
- 사용한 훈장 정의는 삭제하지 않고 사용 중지한다.
- 교사는 경기와 무관하게 평소 생활 중에도 수여할 수 있다. 경기 선택은 필수가 아니다.
- 수여당 소속 원정대에 +10P가 자동 반영된다. 개인 포인트나 훈장별 가변 포인트는 만들지 않는다.
- 기존 학생당 경기별 1개 제한은 폐기한다. 새 일일 제한을 임의로 추가하지 않는다.
- 훈장 수여·포인트 지급은 한 번만 처리하며 경기 저장·재계산으로 중복 지급하지 않는다.

## D-008 · 병력과 구매

- 상태: 확정
- 4종 병력의 가격은 모두 30P이며 구매 수량 제한은 없다.
- 구매가 곧 자동 배치이며 별도 편성 단계는 없다.
- 학생 누구나 팀 QR에서 구매할 수 있다.
- 구매 전 `팀원들과 충분히 상의했나요?` 안내와 가격·잔액을 표시한다.
- 학생은 구매를 취소할 수 없고 교사만 오류를 반대 거래로 복구한다.

## D-009 · 힌트

- 상태: 확정
- 힌트 가격은 100P다.
- 팀별 시즌 1회만 구매할 수 있다.
- 구매 팀과 교사만 볼 수 있다.
- 보스 정체는 숨기고 주된 공격 유형과 유용한 방어 병력을 알려 준다.

## D-010 · 최종 대전과 승점

- 상태: 확정
- 설정한 2~4개 원정대가 같은 보스를 공격하며 최종 대전은 항상 성공한다.
- 팀별 실제 피해량은 그대로 계산한다.
- 남은 보스 체력은 학급 협동 마무리 연출로 제거하고 팀별 피해량에는 넣지 않는다.
- 최고 실제 피해 팀은 누적 승점 1점을 받는다.
- 최고 피해량 동률이면 동률인 모든 팀이 승점 1점씩 받는다.
- 원정 전체 최종 순위는 원정대별 누적 승점, 누적 피해량 순으로 비교하고 모두 같으면 공동 우승이다.
- 보스 체력은 전투 길이 연출을 위해 자동 조정하며 순위·승점에는 영향을 주지 않는다.

## D-011 · 최종 대전 상태와 재생

- 상태: 확정
- 흐름은 `시즌 종료 → 최종 대전 계산 → 애니메이션 확정 → 재생`이다.
- 계산 결과와 재생 이벤트는 한 번 저장하고 새로고침해도 바뀌지 않는다.
- 전투 중에는 피해 숫자만 표시하고 최종 순위는 마지막에 공개한다.
- 교사만 건너뛰기와 같은 결과 다시 보기를 실행할 수 있다.

## D-012 · 영웅 임무

- 상태: 확정
- 영웅 임무는 6개다: 다섯 계단, 빛나는 도전, 빛나는 동료들, 꾸준한 발걸음, 다시 일어선 원정대, 네 가지 힘.
- 다섯 계단은 기준 기록 이후 팀 원기록이 5회 연속 향상해야 한다.
- 빛나는 도전은 도전점퍼 개인 실제 기록이 도전점퍼로 참여한 경기에서 5회 연속 향상해야 한다.
- 빛나는 동료들은 서로 다른 훈장 수상자가 누적 4명 늘 때마다 달성한다. 시즌과 관계없이 누적하며 같은 학생의 반복 수상은 새 인원으로 세지 않는다. 경기 밖의 수여도 포함한다.
- 꾸준한 발걸음은 4경기 연속 2위 이상이다. 2팀 운영에서는 발동하지 않는다.
- 다시 일어선 원정대는 3~4팀 운영에서 직전 꼴찌 후 바로 다음 경기 1위가 되는 것이다. 3팀의 꼴찌는 3위, 4팀의 꼴찌는 4위이며 2팀 운영에서는 발동하지 않는다.
- 네 가지 힘은 네 병력의 완성 세트 수가 늘 때마다 달성한다.
- 시즌이 바뀌어도 필요한 연속·누적 기록은 이어진다.
- 조건을 달성할 때마다 영웅 카드를 받으며 조건별 시즌 1회 제한은 없다.

## D-013 · 영웅 추첨과 수명

- 상태: 확정
- 영웅은 일반 8종·60%, 희귀 5종·30%, 전설 2종·10%다.
- 등급을 먼저 뽑고 해당 등급의 시즌 내 미획득 영웅을 뽑는다.
- 같은 팀은 같은 시즌에 같은 영웅을 다시 뽑지 않는다.
- 소진된 등급 확률은 남은 등급에 비례 재분배한다.
- 한 시즌 최대 15장이며 전종 획득 뒤 추가 달성은 기록만 남긴다.
- 획득 영웅은 선택 없이 모두 현재 시즌 최종 대전에 참여한다.
- 시즌 종료 후 전투 효과는 초기화하고 도감에는 획득 횟수와 기여 학생을 누적한다.

## D-014 · 영웅 공개

- 상태: 확정
- 조건 달성 시 미공개 카드로 지급한다.
- 공개 전 팀원이 함께 볼 준비가 되었는지 안내한다.
- 한 팀원이 열면 접속 중인 같은 팀 화면에 애니메이션을 동시에 재생한다.
- 소리는 공개를 시작한 기기에서만 재생한다.
- 다른 팀에는 영웅 획득 사실과 총 장수만 알리고 정체·등급·효과·진행도는 숨긴다.
- 최종 대전에서 모든 팀의 영웅을 공개한다.

## D-015 · 학생 접속과 정보 공개

- 상태: 확정
- 학생은 개인 가입, 학급 코드, 팀 선택, PIN 없이 팀별 QR로만 접속한다.
- QR을 재발급하면 이전 QR은 무효화한다.
- 학생 이름과 원정대 명단, 기록, 순위, 훈장 수상자는 원정 참여 학생에게 공개한다.
- 다른 팀의 병력, 잔액, 힌트, 영웅 상세는 최종 대전 전까지 숨긴다.

## D-016 · 학생 이동과 정정

- 상태: 확정
- 학생 추가·제외·팀 이동은 교사만 할 수 있다.
- 개인 기록·훈장·도전점퍼 연속 성장은 학생을 따라가고 이미 지급된 원정대 보상은 이전 원정대에 남는다.
- 최종 대전 계산 전까지 교사가 확정 경기를 수정할 수 있다.
- 수정 시 이후 포인트·순위·성장·영웅을 모두 재계산한다.
- 잔액이 부족해지면 교사가 취소할 구매를 직접 선택한 뒤 정정을 확정한다.

## D-017 · 원정 완료

- 상태: 확정
- 설정된 마지막 시즌의 최종 대전이 끝나면 원정이 완료된다.
- 완료 원정은 읽기 전용으로 보관한다.
- 새 원정은 원정대·QR·승점·포인트·병력·영웅·도감·성장 기록을 모두 새로 시작한다.

## D-018 · 첫 등록과 게임 준비 순서 (화면·명칭·팀 수는 D-021로 대체)

- 상태: 확정 · 2026-10-19 사용자 수정
- 처음에는 학급 이름과 전체 학생 명단만 등록한다.
- 교사에게 별도의 원정대 이름을 입력받지 않는다. 학생들이 정하는 팀 이름이 화면의 원정대 이름이다.
- 팀 이름과 팀원 배정은 등록 이후 게임 준비 화면에서 정한다.
- 처음부터 팀별로 명단을 나누거나 시즌·보스까지 모두 설정하도록 요구하지 않는다.
- 전체 명단에서 학생을 골라 3팀에 배정하고, 팀을 옮겨도 같은 학생의 식별 정보를 유지한다.
- 시즌·기간·보스는 게임 준비 화면의 별도 설정에서 교사가 정한다. 실제 경기 전의 확정 규칙은 유지한다.
- 기존 문서의 원정대는 여러 시즌을 묶는 운영 단위로 유지하되, 교사용 별도 작명 입력을 뜻하지 않는다.

## D-019 · 교사 준비 메뉴와 자율적인 시즌 준비 (메뉴 구성은 D-021로 대체)

- 상태: 확정 · 2026-10-20 사용자 수정
- 게임 준비는 `명단 · 팀 편성 · 시즌 · 도전점퍼` 메뉴로 나눈다. 학생 추가를 팀 편성 아래의 부가 입력으로 두지 않는다.
- 명단에서 이름을 고치거나 학생을 추가해도 기존 학생 ID와 팀 배정을 유지한다. 새 학생은 대기 명단에 둔다.
- 최대 5시즌은 상한이지 필수 개수가 아니다. 처음에는 1시즌만 준비하며, 나머지는 필요할 때 추가하거나 준비할 수 있다.
- 여러 시즌을 미리 계획해도 이번에 기록할 시즌 하나의 보스와 기간만 갖추면 된다. 다음 시즌의 미작성 때문에 기록판을 막지 않는다.
- 도전점퍼와 개인별 1~3배는 기록판을 열기 전에 별도 메뉴에서 정한다. 새 기록은 이 지정을 가져와 바로 개수 입력으로 들어간다.
- 별도 확인 버튼을 눌렀는지가 아니라 입력 내용의 준비 여부로 진입을 판단한다. 미완료 항목은 구체적으로 안내하고 해당 메뉴로 이동한다.
- 입력 중인 기존 연습 기록은 당시 스냅샷을 유지한다. 준비 메뉴의 변경은 다음 새 기록에 적용하며 이 차이를 안내한다.
- 공식 시즌 시작·종료와 서버 확정 규칙은 바꾸지 않는다. 현재 단계는 로컬 연습 기록판이다.

## D-020 · 원정대 수에 따른 영웅 임무 조정

- 상태: 확정 · 2026-10-20 사용자 수정
- 빛나는 동료들의 기준을 서로 다른 메달 수상자 누적 5명 증가에서 **4명 증가**로 변경한다. 시즌이 바뀌어도 이어서 세며 4명·8명·12명…마다 달성한다.
- 같은 학생이 메달을 여러 번 받아도 서로 다른 수상자 수에는 한 명으로 센다.
- **2팀 운영에서는 다시 일어선 원정대와 꾸준한 발걸음의 영웅 획득 판정을 비활성화한다.**
- 다른 네 임무는 2팀이라는 이유로 비활성화하지 않는다.
- 이 결정은 영웅 임무 규칙 변경이며, 아직 없는 서버 보상 엔진을 구현했다는 뜻은 아니다.

## D-021 · 원정 목록과 현황 중심 운영 구조

- 상태: 사용자 요청 반영 · 2026-10-20. 상세 개편안은 `docs/operation-flow-reorganization.md` 참조.
- `원정 시작하기 → 원정 목록 → 원정 선택 → 현황판`으로 연결한다. 새로 시작/이어가기 중간 선택창은 없앤다.
- 목록에서 기존 원정을 보여 주고 `원정 만들기`로 생성한다. 학급 생성이라는 화면 용어를 사용하지 않는다.
- 전체 운영 묶음은 원정, 개별 팀은 원정대라는 용어로 구분한다. 앱 이름은 줄넘기 원정대로 유지한다.
- 상위 메뉴는 현황·명단·시즌 설정 세 개다. 기록하기는 현황판의 주요 버튼으로 제공한다.
- 현황판은 현재 시즌·기간·경기 수, 원정대 이름·대장·대원·도전점퍼, 최근 순위·현재 포인트·최종 대전 누적 승점을 구분해 보여 준다.
- 명단에서 원정대 이름·대표 학생·편성·도전점퍼·배수를 함께 관리한다. 팀 편성과 도전점퍼를 독립 상위 메뉴로 두지 않는다.
- 학생 30명 안팎을 고려해 작은 행으로 표시한다. 학생 추가는 별도 버튼으로 모달을 열어 처리한다.
- 원정대 수는 3개 고정에서 교사 선택 2~4개로 확장한다. 4위 보너스는 0P로 확정했으며 진행 중 수 변경 등 남은 미정 규칙은 개편 문서에서 구분한다.
- 기존 학생 ID·저장 이름·연습 기록을 보존한다. 화면 용어를 바꾸면서 내부 ID와 저장 키를 일괄 교체하지 않는다.

## D-022 · 일상 훈장 수여와 현황 표시

- 상태: 확정 · 2026-10-20 사용자 수정
- 훈장은 경기 외 평소 생활 중에도 교사가 수여한다. 경기 연결과 경기당 수여 한도는 요구하지 않는다.
- 훈장 1개를 주면 수여 당시 소속 원정대가 자동으로 10P를 받는다. 경기 기록 확정·재계산으로 재지급하지 않는다.
- 명단 안의 훈장 관리에서 이름·설명·아이콘/이미지를 커스텀한다. 별도 상위 메뉴는 추가하지 않는다.
- 명단 또는 현황판에서 학생을 선택하면 같은 상세창을 열고 훈장을 줄 수 있다.
- 현황판 이름 옆에는 훈장 이미지만 표시하고, 학생을 누르면 이름·설명·수여 이력·횟수를 자세히 보여 준다. 같은 종류는 아이콘 하나로 묶고 상세에서 횟수를 확인한다.
- 일상 훈장도 빛나는 동료들에 포함한다. 반복 수여당 +10P는 각각 지급하되, 서로 다른 수상자 수는 중복 계산하지 않는다.
- 진행 중 시즌이 없거나 원정대에 미배정된 학생의 보상 귀속은 미정이다. 포인트 이월·보류 정책을 임의로 추가하지 않는다.
- 아직 공식 보상 엔진은 연결하지 않았다. 이번 갱신은 규칙과 개편 계획 정리다.

## D-023 · 디자인 보류와 로컬 기능 우선

- 상태: 확정 · 2026-10-20 사용자 요청 및 로컬 우선 선택
- 학급/원정 카드 등 전체 웹디자인 재작업은 보류하고 기능 뼈대부터 완성한다.
- 구현 순서는 훈장 관리·수여 → 포인트·구매 → 영웅 → 시즌 종료·최종 대전이다.
- 로그인·실제 서버·기기 간 동기화는 로컬 전체 흐름을 만든 뒤 연결한다.
- 로컬 훈장 수여와 +10P는 별도 연습 저장소에 기록한다. 공식 권한·실제 서버 장부로 표현하지 않는다.
- 기존 공식 운영의 서버 트랜잭션·멱등성·권한 규칙은 폐기하지 않는다. 서버 연결 단계에서 구현한다.
- 미정 규칙은 계속 임의 결정하지 않는다. 로컬 수여는 학생 소속과 준비된 기록 시즌이 있을 때만 제공하고, 종료/미설정 시즌 및 미배정 학생의 귀속 처리는 남겨 둔다.

## D-024 · 내일 사용을 위한 학생 읽기 전용 공개

- 상태: 사용자 우선순위 반영 · 2026-10-20. D-023의 전체 로컬 완료 후 서버 연결 순서를 명단 공개 범위에 한해 앞당긴다.
- 내일은 교사가 학생 명단을 넣고 원정대를 구성하며, 학생은 자기 원정대 명단과 병력·영웅 카드만 둘러본다. 학생 수정·구매·경기 입력은 제공하지 않는다.
- 도감은 실제 획득 카드가 아니다. 비밀 보스·개인 배수·배치 전략은 공개 자료에 포함하지 않는다.
- 2026-10-21 변경: 교사는 화면에서 이메일 없이 아이디와 비밀번호로 가입·로그인한다. 앱은 Supabase 이메일 인증과 호환되는 내부 주소로 아이디를 변환하며, 원정 자료는 `owner_id` RLS로 계정별 분리한다. 학생은 가입하지 않고 원정대별 공개 토큰 QR로 읽는다.
- 준비 원본은 교사 브라우저에 유지하고 명시적인 게시 때 서버 스냅샷을 만든다. 편성 변경 후 재게시가 필요하며 실시간 자동 동기화로 표현하지 않는다.
- 같은 원정대를 다시 게시하면 토큰을 유지한다. QR 재발급은 확인 후 기존 토큰을 무효화한다. 링크를 아는 사람은 읽을 수 있으므로 학급 외부에 게시하지 않는다.
- GitHub 저장소는 사용자가 제공했으며 Vercel Git 연결은 사용자가 한다. Supabase 프로젝트 설정과 실제 기기 간 검증은 별도 완료가 필요하다.
- 강한 초록덕후 장식을 줄이고 현재 게임 정체성을 살린 간결한 운영 UI로 정돈한다. 기존 영웅·포인트·시즌 규칙은 변경하지 않는다.

## D-025 · 공기왕식 훈장 만들기와 빠른 수여

- 상태: 확정 · 2026-10-21 사용자 요청. D-022의 아이콘/이미지 직접 선택 방식을 대체한다.
- 훈장 모양은 앱이 제공하는 하나의 완성형 벡터 이미지를 사용한다. 교사는 이름·설명과 6가지 색상만 고른다.
- 이미지 업로드와 아이콘 종류 선택은 새 훈장 화면에서 제거한다. 기존 저장 이미지와 과거 수여 스냅샷은 읽기 호환을 유지한다.
- `훈장 만들기`와 `학생에게 수여`를 한 창의 두 단계로 제공한다. 만들어 둔 훈장과 학생을 고른 뒤 한 번의 버튼으로 수여한다.
- 학생 상세에서는 훈장 선택 목록과 별도 확인 단계를 없애고, 훈장 카드를 한 번 눌러 바로 수여한다.
- 반복 수여, 수여당 소속 원정대 +10P, 사용 중지, 과거 이력 보존 규칙은 바꾸지 않는다.

## D-026 · 공식 경기 확정과 포인트 감사 원장

- 상태: 확정 · 2026-10-21 사용자 요청. D-019의 로컬 연습 기록판 범위를 대체한다.
- 교사가 기록 결과를 확인한 뒤 명시적으로 확정해야 공식 경기와 팀 포인트가 서버에 기록된다.
- 확정 경기 ID는 멱등 키다. 같은 요청 재전송은 중복 지급하지 않고, 같은 ID의 다른 결과는 거절한다.
- 오입력은 기록을 삭제·수정하지 않는다. 3~200자의 사유와 취소 시각을 남기고 기존 지급액의 반대 거래를 추가한다.
- 공식 경기와 포인트 원장은 교사 소유 RLS로 보호하고, 쓰기는 하나의 서버 트랜잭션을 사용하는 검증 RPC로만 처리한다.
- 기존 로컬 연습 기록은 보존하지만 자동으로 공식 포인트로 승격하지 않는다.
- 4위 순위 보너스는 0P로 확정했다. 참가 30P와 성장 보너스는 동일하게 적용하며 4팀 경기도 공식 확정할 수 있다.

## D-027 · 4팀 순위와 역전 임무 확정

- 상태: 확정 · 2026-10-21 사용자 확인
- 4위 순위 보너스는 0P다. 따라서 성장 보너스가 없을 때 4위의 경기 지급 합계는 참가 30P다.
- 다시 일어선 원정대는 팀 수와 관계없이 `직전 경기 꼴찌 → 바로 다음 경기 1위`라는 뜻으로 판정한다.
- 3팀에서는 3위 → 1위, 4팀에서는 4위 → 1위다. 2팀 운영에서는 기존 결정대로 발동하지 않는다.

## D-028 · 로컬 영웅 판정·보관함 구현

- 상태: 구현 · 2026-10-21
- 공식 경기·훈장·병력 구매 원본에서 6개 임무 달성을 다시 계산하고, 달성 ID별로 미공개 영웅 카드 한 장을 한 번만 만든다.
- 등급 확률과 시즌 내 무중복·등급 풀 소진 시 확률 재분배·15종 소진 후 달성 기록만 보존하는 규칙을 적용한다.
- 공개 전에는 영웅 ID를 화면 DOM에 넣지 않고 팀원 전체가 함께 보는지 확인한다. 공개 후 이름·등급·효과와 기여 학생을 보여 준다.
- 현재 결과는 로컬 영웅 저장소와 교사 계정 전체 스냅샷에 보존한다. 서버 권한 추첨, 정정에 따른 회수 감사, 학생 QR 실시간 동시 공개는 별도 서버 단계로 남긴다.

## D-029 · 결정론적 시즌 종료·최종 대전 구현

- 상태: 구현 · 2026-10-22
- 현재 시즌은 기간 전에도 교사가 종료할 수 있다. 공식 경기가 0경기면 종료하지 않고, 계산 전에는 종료를 취소할 수 있다.
- 계산할 때 병력·영웅·도전점퍼 추가 효과·보스와 규칙 버전 `battle-v1`을 고정한다. 계산 뒤에는 공식 경기 변경과 팀 준비를 잠근다.
- 보스별 공격 비중·상성, 방어 행동 가능 시간, 영웅 H01~H15 효과를 적용해 피해량과 순위를 계산한다. 최고 피해 동률은 모두 승점 1점이며 임의 추첨으로 순위를 깨지 않는다.
- 연출용 보스 체력에서 원정대 피해량을 뺀 나머지는 협동 마무리로 기록하고 개별 순위 피해량에는 더하지 않는다.
- 보스 등장·공격·협동 마무리·결과 이벤트를 저장해 건너뛰기와 다시 재생이 같은 결과를 사용한다. 완료 후 다음 준비된 시즌으로 이동하고 시즌별 결과와 누적 승점을 보존한다.
- 현재 계산 권한과 저장은 교사 로컬 및 계정 스냅샷 단계다. 서버 트랜잭션·결과 서명·정정 감사는 후속 전환 범위다.

## D-030 · 학생 QR 영웅 공개 경계와 자동 갱신

- 상태: 구현 기반 · 2026-10-22
- 학생 공개 자료에는 자기 원정대의 현재 시즌 봉인 카드 슬롯과 공개 완료 영웅 ID만 넣는다. 봉인 영웅의 ID와 다른 원정대 영웅 정보는 공개하지 않는다.
- 기존 QR이 있으면 영웅 상태 변경 뒤 토큰을 바꾸지 않고 다시 게시한다. 이 단계의 2.5초 영웅 탭 갱신은 D-031의 전체 화면 1초 예약 공개로 대체한다.
- 학생 화면은 읽기 전용이다. 학생이 공개를 시작하거나 구매·전략을 변경할 수 없다.
- 이 결정 당시 남겼던 기기 간 공개 애니메이션과 서버 권한 추첨은 D-031에서 구현했다. 정정·회수 감사는 계속 후속 범위다.

## D-031 · 영웅·최종 대전 서버 권한과 예약 공개

- 상태: 구현, 실제 Supabase 적용 전 · 2026-10-22
- 영웅 임무 판정은 기존 원본 기록에서 계산하되, 서버 연결 환경에서는 달성 ID별 영웅 토큰을 서버 함수가 한 번만 추첨한다. 같은 요청은 같은 결과를 돌려주며 팀·시즌 내 영웅 중복을 데이터베이스 제약으로 막는다.
- 기존 로컬 영웅 기록은 첫 서버 동기화 때 공개 여부를 포함해 이어받는다. 이후 서버에 이미 저장된 달성 결과와 다른 로컬 값은 서버 결과로 교체한다.
- 영웅 공개는 서버가 약간 뒤의 공개 시각을 확정한다. 교사 화면과 같은 팀 QR 화면은 그 시각을 기준으로 연출을 시작하며 다른 팀에는 이벤트와 영웅 ID를 보내지 않는다.
- 최종 대전 공식은 브라우저와 Edge Function이 함께 쓰는 순수 모듈로 분리한다. 서버는 공식 경기 수와 서버 영웅 목록을 대조하고 피해량·동률 승점·이벤트를 직접 다시 계산해 시즌별 한 결과만 불변 저장한다.
- 학생 화면은 Supabase Realtime 채널 대신 1초 간격의 읽기 전용 확인을 사용한다. 서버 시각으로 시작점을 맞추지만 네트워크 지연에 따른 약 1초 이내 차이는 허용한다.
- 병력 구매와 훈장 원장은 아직 같은 서버 권한 단계로 옮기지 않았다. 따라서 최종 대전의 병력 입력은 교사 스냅샷에서 오며, 이 부분은 구매·훈장 서버 거래 장부 전환 때 추가 검증한다.

## 구현 시 금지

- 시간 정규화 점수나 경기별 승점을 새로 만들지 않는다.
- 학생용 `리그`, `레이드`, `리그 포인트` 용어를 되살리지 않는다.
- 학급 코드·팀 선택·PIN 접속 흐름을 구현하지 않는다.
- 최고 피해 동률을 임의 추첨으로 깨지 않는다.
- 다른 팀의 전략 정보를 공개하지 않는다.
- 경기 운영 예외를 앱이 대신 판정하도록 범위를 넓히지 않는다.
