# 학급 등록과 게임 준비 화면

> 이 문서는 개편 전 준비 UI의 구현 이력이다. 현재 현황 중심 UI는 `operation-screen-implementation.md`, 전체 목표는 `operation-flow-reorganization.md`와 결정 로그 D-021·D-022를 따른다. 아래 학급 용어·4개 준비 메뉴·3팀 고정은 이전 구조이며 새 운영 동선의 기준으로 사용하지 않는다.

## 기준

2026-10-20 사용자 수정 D-019와 첫 등록 결정 D-018을 우선한다. 처음부터 팀을 편성하거나 별도의 원정대 이름을
교사가 정하도록 요구하지 않는다. 여러 시즌을 묶는 내부 운영 단위와 학생 팀 이름은 별도로 다룬다.

## 흐름

1. 처음에는 학급 이름과 전체 학생 명단만 입력한다.
2. 명단을 저장하면 해당 학급의 게임 준비 화면으로 들어간다.
3. 대기 명단에서 학생을 골라 1·2·3팀에 배정한다.
4. 게임 화면에서 학생들과 각 팀 이름을 정한다. 이 이름이 학생들이 사용하는 원정대 이름이다.
5. 팀원 옆 버튼으로 대기 명단으로 옮긴 뒤 다른 팀에 다시 배정할 수 있다.
6. 학생 추가와 이름 수정은 별도의 `명단` 메뉴에서 한다. 기존 팀 배정과 학생 ID를 유지한다.
7. `시즌` 메뉴에서 이번 시즌의 기간·보스만 정한다. 기본 1개, 최대 5개이며 나머지는 필요할 때 추가한다. 전체 시즌 수를 미리 정하는 기능은 선택 사항이다.
8. 준비 내용 저장은 실제 시즌이나 경기를 시작하지 않는다.
9. `도전점퍼` 메뉴에서 팀별 학생 1~2명과 개인별 1~3배를 정한다.
10. 세 팀·시즌 하나·도전점퍼가 준비되면 바로 연습용 경기 기록판의 개수 입력을 연다. 별도 확인 이력이나 미작성 미래 시즌은 진입 조건이 아니다. 부족한 항목은 해당 메뉴로 안내한다. 공식 경기 확정은 하지 않는다.

## 데이터와 저장

- 학생마다 고유 ID를 만들어 동명이인과 팀 이동을 구분한다.
- 이름 옆 순번은 명단 입력 순서다. 학생의 고유 ID나 공식 출석 번호는 아니다.
- 팀원은 이름을 다시 입력하는 대신 등록 학생 ID로 배정한다.
- 학생을 옮기면 이전 팀에서 빼고 새 팀에 넣어 중복 배정을 방지한다.
- 최초 등록에는 팀 편성이나 시즌 검증을 적용하지 않는다.
- 진입할 때 3팀의 이름과 최소 한 명 이상의 팀원을 확인한다.
- 선택한 시즌 하나의 중복 없는 보스와 유효한 기간을 확인한다. 미래 시즌은 미작성 상태로 둘 수 있다.
- 팀·시즌의 이전 확인 플래그는 저장 호환을 위해 유지하지만 진입을 막는 조건으로 사용하지 않는다.
- `jumpers`에 팀별 학생 ID와 1~3배 지정을 자동 저장한다. 이전 데이터에 이 필드가 없어도 읽을 수 있다.
- 작성 중인 전체 명단은 `jre.preparation.draft.v2`, 등록한 학급과 게임 준비 내용은 `jre.preparations.v2`에 저장한다.
- 변경은 같은 브라우저에 자동 저장하며 실패하면 화면의 입력을 유지하고 안내한다.
- v1 준비안은 기존 명단·팀·시즌을 v2 구조로 변환해 읽는다. 기존 저장 완료된 원본 키를 보존한다.
- 기존 교사용 원정대 이름은 새 화면의 입력이나 학급 제목으로 사용하지 않는다.

## 디자인

주아 제목·버튼, 크림 종이와 짙은 초록 기준선을 유지한다.
초기 화면에는 단계 진행표를 두지 않는다. 게임 준비에서는 장식용 좌측 영역을 줄이고 `명단 · 팀 편성 · 시즌 · 도전점퍼` 메뉴와 다음 할 일을 보여준다.
팀 번호·이름과 초록·황금·파랑 색상을 함께 사용한다. 학생 선택과 배정은 마우스·키보드로 가능하다.

## 아직 연결하지 않은 범위

교사 인증·학급 소유권, Supabase 저장, 실제 경기 시작과 팀 QR 발급·기기 간 동기화는 후속 단계다.
지금 화면은 교사용 로컬 게임 준비 화면이며 학생에게 공유하는 보드가 아니다.
