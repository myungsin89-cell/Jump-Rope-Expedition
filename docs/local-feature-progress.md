# 로컬 기능 우선 개발 현황

> 2026-10-20 · 아래 순서는 학생용 읽기 전용 공개를 우선하는 최신 요청으로 일부 변경되었다.

## 최신 우선순위: 내일 팀 구성과 카드 둘러보기

- 교사 명단·팀 구성과 기존 연습 기능은 유지한다. 학생은 자기 원정대 명단, 병력 4종, 영웅 15종만 본다. 구매·수정·보스·전략 공개는 없다.
- 학생 미리보기는 로컬에서 작동한다. 서버 설정 전에는 다른 기기에 쓸 QR을 만들어 공유가 된 것처럼 표시하지 않는다.
- Supabase의 공개 스냅샷 테이블과 임시 교사 게시 키 방식의 Edge Function 소스를 추가했다. 키 없는 공개 읽기는 토큰으로만, 쓰기는 교사 키로만 허용한다.
- 명단 게시 시 비공개 준비 정보도 서버에 백업하지만, 연습 경기·훈장·공식 잔액 전체를 서버로 옮긴 것은 아니다. 교사 브라우저 원본을 지우지 않는다.
- 교사 로그인은 이후 제품화 때 연결한다. 서버 실제 배포·환경 변수 설정·휴대기기 QR 검증이 남아 있다. [첫 배포 안내](./first-deployment-guide.md)를 따른다.
- 최신 검증: 단위/API 경계 테스트 83개, 브라우저 회귀 26개, 타입·배포 빌드 통과. 전체 ESLint에는 기존 `IntroStorybookModal.tsx`의 React Hooks 관련 오류 6개가 남아 있다. 이번 변경 파일은 별도로 검사한다.

아래의 ‘QR는 후속 단계’ 및 순서 4는 위의 명단 공개 범위에 한해 대체된다. 공식 보상·전투 서버 요구는 그대로다.

## 이번 단계: 훈장 관리와 수여

- 명단 → 훈장 관리: 기본 훈장 없이 교사가 이름·설명·아이콘을 지정한다. 직접 만든 PNG/JPG/WebP 이미지도 등록한다. 브라우저 저장 용량을 고려해 파일은 200KB, 가로·세로는 각 2048px 이하로 제한한다. SVG/원격 URL은 받지 않는다.
- 훈장은 수정·사용 중지·다시 사용이 가능하다. 사용 중지해도 과거 수여 이력을 삭제하지 않는다.
- 명단/현황 → 학생 이름 → 받은 훈장 펼치기 → 훈장 선택 → 훈장 주기 → 수여 확정.
- 경기 연결이나 경기당 횟수 제한은 없다. 의도적인 반복 수여는 매번 10P다. 별도 포인트 입력 옵션은 없다.
- 학생 이름 옆은 같은 훈장 종류당 아이콘 하나만 표시한다. 학생 상세에는 종류별 횟수·설명과 수여 날짜·시즌·당시 소속이 나온다.
- 수여 당시 훈장 정의·학생 이름·원정대 이름을 스냅샷으로 보존한다. 정의 수정이나 학생 이동으로 과거 기록을 다시 쓰지 않는다.
- 학생이 이동해도 훈장은 학생 ID를 따라가고, 이미 반영한 포인트와 당시 팀의 수상자 기록은 이전 원정대에 남는다.
- 빛나는 동료들 진행도는 수여 당시 원정대의 서로 다른 학생 ID로 계산한다. 시즌과 무관하게 4명·8명·12명… 기준이며 반복 수여나 동명이인을 이름으로 세지 않는다. 실제 영웅 추첨/지급은 다음 단계다.

## 로컬 데이터와 포인트

- 새 저장 키: `jre.practice-medals.v1.<원정 ID>`.
- 한 문서에 훈장 정의, append-only 수여 이벤트, 수여 ID와 1:1인 +10P 장부 항목을 담는다. 기존 명단·연습 경기 저장 키는 변경하지 않는다.
- 수여 이벤트와 +10P 항목을 한 번의 `localStorage.setItem`으로 저장한다. 저장 실패 시 이전 문서는 유지되고 재시도할 수 있다.
- 같은 수여 요청 ID 재전송은 추가 지급하지 않는다. 같은 ID를 다른 학생·훈장에 재사용하면 거절한다. 새로 확정한 반복 수여는 새 요청이다.
- 현황의 연습 획득 합계 = 기존 경기 예상 포인트 + 선택 시즌의 훈장 포인트. 4위 미정이 포함되면 여전히 `일부 미정`이며 임의의 0P로 대체하지 않는다.
- 경기 기록 저장·재계산은 훈장 장부에 쓰지 않는다. 경기와 훈장 포인트를 중복 반영하지 않는다.
- 시즌별 포인트는 분리하고 훈장 개인 이력과 수상자 누적은 시즌을 넘어 유지한다.
- 훈장 수여 이후 원정대 수·기존 시즌 순서를 잠가 팀/시즌 인덱스가 달라지는 것을 막는다. 이름과 학생 편성은 변경 가능하다.
- 손상/형식 불일치가 있으면 원본을 보존하고 훈장 쓰기를 막는다. 현황은 0P 대신 `확인 필요`로 표시한다.

현재는 **단일 브라우저 로컬 연습 데이터**다. 로그인 권한, 서버 원자성, 여러 기기/탭의 동시 수정 보장, 자동 백업은 없다. 브라우저 데이터 삭제 시 소실될 수 있다. 서버 연결 때 이 데이터를 무검증 공식 포인트로 가져오면 안 된다.

## 아직 정하지 않았거나 구현하지 않은 것

- 기록할 시즌이 미설정이거나 학생이 미배정이면 로컬 수여도 보류한다. 미정인 포인트 이월/귀속 정책을 만들지 않는다.
- 현재 귀속 시즌은 교사가 선택한 **준비된 기록 시즌**이다. 실제 시즌 시작/종료 수명 주기는 다음 단계이며 날짜로 자동 판단하지 않는다.
- 잔액과 구매 장부, 병력·힌트 구매, 영웅 추첨·카드 공개, 최종 대전, 학생 QR는 후속 단계다.
- 공식 운영의 교사 인증·RLS·서버 트랜잭션·멱등성·정정 감사 장부 요구는 유지한다.

## 검증

- 훈장 도메인 단위 테스트 11개: 빈 초기 상태, 정의 검증, 고정 10P, 요청 멱등성, 반복/서로 다른 수상자, 시즌 분리, 이동·중지·스냅샷, 미정 귀속 보류, 실패 재시도, 손상 자료 보존, 팀 수 보호.
- 전체 단위 테스트 72개 통과.
- 브라우저 훈장 테스트 5개: 생성·반복 수여·아이콘·이력·합계, 실패 재시도와 이동, 이미지 등록·정의 수정/중지, 모바일·미배정 차단, 손상 원본 보존.
- 기존 화면을 포함한 브라우저 회귀 24개 통과. 타입 검사·빌드·수정 범위 ESLint를 함께 확인한다.
- 조작 스킬은 기존 UI 재사용 및 키보드 포커스·모달 복귀 검수에만 적용했다. 신규 시각 디자인 작업은 하지 않았다.

## 이어갈 순서

1. 로컬 포인트 잔액·획득/사용 장부를 분리하고 병력 30P·힌트 100P 구매를 연결한다.
2. 영웅 6개 임무의 판정·중복 없는 추첨·공개·시즌 도감 이관을 연결한다. 미정인 4팀 역전 조건은 구현 직전에 확인한다.
3. 시즌 수동 종료 → 계산 → 애니메이션 확정 → 재생 흐름과 최종 대전을 연결한다.
4. 전체 로컬 흐름을 검증한 뒤 로그인·실제 저장 서버·QR·동기화를 연결한다.
