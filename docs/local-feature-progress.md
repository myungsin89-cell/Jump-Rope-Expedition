# 로컬 기능 우선 개발 현황

> 2026-10-22 최신화: 학생 원정대 게시판의 서버 구매(병력·힌트) 및 봉인 영웅 개봉 기능이 구현 완료되었습니다.

## 최신 우선순위: 팀 구성, 학생 게시판, 상점과 병력

- 교사 명단·팀 구성과 공식 경기 기록 기능을 제공한다. (과거 초기 상태) 초기에는 학생이 자기 원정대 명단, 병력 4종, 영웅 15종만 확인하는 읽기 전용으로 출발했으나, 현재는 학생 게시판에서 전체 원정대 열람, 학생별 훈장·성장 기록, 포인트 확인, 병력·힌트 서버 구매, 보유 병력 확인, 봉인 영웅 알림 및 개봉까지 모두 지원하도록 완료되었다.
- 학생 미리보기는 로컬에서 작동한다. 서버 설정 전에는 다른 기기에 쓸 QR을 만들어 공유가 된 것처럼 표시하지 않는다.
- Supabase의 공개 원정대 게시판과 교사 계정별 원정 스냅샷을 추가했다. 공개 읽기는 토큰으로만, 게시 쓰기는 검증한 교사 JWT로만 허용한다.
- 새 원정 저장 시 명단·경기·훈장·구매 스냅샷이 자동 백업되며, 원정 목록에서 로그인한 교사 계정 자료로 자동 동기화된다. 공식 경기 확정·취소와 팀 포인트는 별도 서버 원장에도 기록한다.
- 교사 아이디 로그인과 `owner_id` 기반 RLS를 연결했다. 가입에는 영문 소문자·숫자 4~20자 아이디, 6자 이상 비밀번호와 비밀번호 확인을 사용한다. 실제 수업 전 로그인·휴대기기 QR 확인을 한 번 더 진행한다. [첫 배포 안내](./first-deployment-guide.md)를 따른다.
- 최신 검증 수치는 각 배포 직전 전체 테스트에서 갱신한다. Supabase 학생 게시판과 공식 경기·포인트 원장이 연결되어 있다.

아래의 ‘QR는 후속 단계’ 및 순서 4는 위의 학생 게시판 지원 범위에 한해 대체된다. 공식 보상·전투 서버 요구는 그대로다.

## 이번 단계: 훈장 관리와 수여

- 명단 → `훈장 만들기·수여`: 공기왕과 같은 완성형 훈장 벡터를 사용하고 교사는 이름·설명·6가지 색상만 정한다. 이미지 업로드와 아이콘 종류 선택은 제거했다.
- 훈장은 수정·사용 중지·다시 사용이 가능하다. 사용 중지해도 과거 수여 이력을 삭제하지 않는다.
- 훈장 창의 `학생에게 수여`에서 훈장·학생을 골라 한 번에 수여한다. 명단/현황에서 학생 이름을 연 뒤에는 훈장 카드를 한 번 눌러 바로 수여할 수도 있다.
- 경기 연결이나 경기당 횟수 제한은 없다. 의도적인 반복 수여는 매번 10P다. 별도 포인트 입력 옵션은 없다.
- 학생 이름 옆은 같은 훈장 종류당 아이콘 하나만 표시한다. 학생 상세에는 종류별 횟수·설명과 수여 날짜·시즌·당시 소속이 나온다.
- 수여 당시 훈장 정의·학생 이름·원정대 이름을 스냅샷으로 보존한다. 정의 수정이나 학생 이동으로 과거 기록을 다시 쓰지 않는다.
- 학생이 이동해도 훈장은 학생 ID를 따라가고, 이미 반영한 포인트와 당시 팀의 수상자 기록은 이전 원정대에 남는다.
- 빛나는 동료들 진행도는 수여 당시 원정대의 서로 다른 학생 ID로 계산한다. 시즌과 무관하게 4명·8명·12명… 기준이며 반복 수여나 동명이인을 이름으로 세지 않는다. 기준을 채울 때마다 해당 팀의 영웅 보관함에 봉인된 보상 1장이 생성된다.

## 훈장 데이터와 포인트

- 새 저장 키: `jre.practice-medals.v1.<원정 ID>`.
- 한 문서에 훈장 정의, append-only 수여 이벤트, 수여 ID와 1:1인 +10P 장부 항목을 담는다. 기존 명단·연습 경기 저장 키는 변경하지 않는다.
- 수여 이벤트와 +10P 항목을 한 번의 `localStorage.setItem`으로 저장한다. 저장 실패 시 이전 문서는 유지되고 재시도할 수 있다.
- 같은 수여 요청 ID 재전송은 추가 지급하지 않는다. 같은 ID를 다른 학생·훈장에 재사용하면 거절한다. 새로 확정한 반복 수여는 새 요청이다.
- 현황의 경기 획득 합계 = 취소되지 않은 공식 경기 포인트 + 선택 시즌의 훈장 포인트. 기존 연습 기록은 공식 합계에 포함하지 않는다.
- 경기 기록 저장·재계산은 훈장 장부에 쓰지 않는다. 경기와 훈장 포인트를 중복 반영하지 않는다.
- 시즌별 포인트는 분리하고 훈장 개인 이력과 수상자 누적은 시즌을 넘어 유지한다.
- 훈장 수여 이후 원정대 수·기존 시즌 순서를 잠가 팀/시즌 인덱스가 달라지는 것을 막는다. 이름과 학생 편성은 변경 가능하다.
- 손상/형식 불일치가 있으면 원본을 보존하고 훈장 쓰기를 막는다. 현황은 0P 대신 `확인 필요`로 표시한다.

공식 경기 확정과 취소는 교사 인증·서버 트랜잭션·멱등성·감사 원장을 사용한다. 로컬에는 입력 복구와 빠른 화면 표시를 위한 사본을 유지하고, 전체 원정 스냅샷을 교사 계정에 동기화한다. 기존 연습 기록은 자동으로 서버 공식 포인트로 승격하지 않는다.

## 이번 단계: 로컬 포인트와 구매

- 현황의 원정대별 `팀 준비`에서 선택 시즌의 경기·훈장 획득, 사용, 현재 잔액을 분리해 확인한다.
- 병력 4종은 종류와 관계없이 1명당 30P이며 구매 수량 제한이 없다. 구매 수량이 곧 최종 대전 배치 수량이다.
- 비밀 보스 힌트는 원정대별 시즌당 한 번, 100P다. 보스 이름은 숨기고 주 공격 유형과 유용한 방어 병력만 보여 준다.
- 구매 전 현재 잔액·가격·구매 후 잔액과 필수 상의 문구를 보여 준다. 같은 구매 요청 ID 재전송은 추가 차감하지 않는다.
- 구매와 교사 복구는 삭제·수정 대신 append-only 구매·반대 거래로 남긴다. 복구에는 3자 이상의 사유가 필요하다.
- 구매 저장 키는 `jre.practice-economy.v1.<원정 ID>`다. 경기·훈장 원본 저장소와 합치지 않으며, 손상된 구매 자료는 덮어쓰지 않고 구매를 막는다.
- 4팀 경기의 4위 순위 보너스는 0P다. 참가 30P와 성장 보너스는 다른 순위와 동일하게 적용한다.
- 구매가 시작되면 기존 시즌·원정대 식별자를 보호하기 위해 원정대 수와 시즌 순서 변경을 잠근다.
- (과거 상태) 과거에는 학생 공개 화면이 읽기 전용 계약이었으나, 현재는 학생 원정대 게시판에서 Supabase 서버 거래로 병력 및 힌트 구매가 가능하도록 구현 완료되었다.

## 이번 단계: 로컬 영웅 임무와 공개

- 공식 경기·훈장 수상자·병력 구매 기록에서 영웅 임무 6개를 자동 판정한다.
- 다섯 계단과 빛나는 도전은 기준 기록 뒤 5회 연속 향상, 꾸준한 발걸음은 4경기 연속 2위 이상으로 판정하고 보상 뒤 새 주기를 시작한다.
- 다시 일어선 원정대는 3~4팀에서 직전 꼴찌 후 다음 경기 1위이며 2팀에서는 꾸준한 발걸음과 함께 비활성화한다.
- 빛나는 동료들은 서로 다른 훈장 수상자 4명마다, 네 가지 힘은 시즌별 네 병력 완성 세트가 늘 때마다 달성한다.
- 등급은 일반 60%·희귀 30%·전설 10%로 먼저 정하고 소진된 등급 확률은 남은 등급에 재분배한다. 같은 원정대는 같은 시즌에 같은 영웅을 다시 받지 않는다.
- 현황의 원정대별 `영웅 보관함`에서 미공개 카드 수, 6개 임무 달성 횟수, 현재 시즌 영웅과 지난 시즌 도감을 확인한다.
- 공개 전 모든 팀원이 함께 보는지 묻고, 공개 뒤에만 이름·등급·효과를 DOM에 표시한다. 공개 결과는 다시 뽑지 않고 영웅 저장소와 교사 계정 스냅샷에 보존한다.
- 서버 연결 전에는 추첨과 공개 애니메이션이 교사 화면 한 기기에서 진행된다. 서버 연결 뒤에는 추첨·공개 시각을 서버가 확정하고 같은 원정대 QR 화면에 예약 공개 이벤트를 반영한다. 정정·회수 감사 장부는 후속 단계다.

## 이번 단계: 시즌 종료와 최종 대전

- 교사는 기간이 남아 있어도 현재 시즌을 수동 종료할 수 있다. 공식 경기가 0경기면 종료 자료를 만들지 않고 안내하며, 계산 전에는 종료를 취소할 수 있다.
- `종료 확인 → 계산·확정 → 애니메이션 재생 → 결과` 네 단계로 나눈다. 계산 뒤에는 경기 취소·추가와 팀 준비를 잠그고 같은 입력으로 다시 계산하지 않는다.
- 계산 시점의 병력·영웅·도전점퍼 추가 효과·보스와 규칙 버전 `battle-v1`을 함께 고정한다. 영웅 H01~H15 효과, 보스별 공격 비중과 상성, 방어 병력의 행동 가능 시간을 적용한다.
- 원정대별 피해량과 순위를 계산하고 최고 피해 동률은 모두 승점 1점을 받는다. 보스 체력은 연출용으로 두며 원정대 피해량 합계를 넘는 남은 체력은 모든 원정대의 협동 마무리로 처리해 순위에 더하지 않는다.
- 보스 등장·원정대 공격·협동 마무리·결과 이벤트를 저장한다. 교사는 애니메이션을 건너뛰거나 결과 화면에서 다시 재생할 수 있고, 시즌별 결과와 누적 승점을 현황에서 확인한다.
- 최종 대전 계산 시 해당 시즌의 봉인 영웅을 모두 공개한다. 결과와 이벤트는 로컬 저장소와 교사 계정 스냅샷에 포함한다.

## 다음 단계 기반: 학생 QR 영웅 자동 동기화

- 학생 공개 자료에는 자기 원정대의 현재 시즌 봉인 카드 슬롯과 공개 완료 영웅 ID만 넣는다. 봉인 카드의 영웅 ID와 다른 원정대 영웅은 보내지 않는다.
- 이미 게시한 QR이 있으면 교사 화면의 영웅 변경 뒤 같은 토큰으로 다시 게시한다.
- (과거 상태) 초기에는 학생 화면이 읽기 전용이었으나, 현재는 학생 게시판에서 봉인된 영웅 카드를 직접 눌러 개봉할 수 있고 병력·힌트 서버 구매도 가능하다. 다른 원정대의 미공개 영웅·보스·배치·개인 배수를 비공개로 유지하는 보안 경계는 유지된다.

## 이번 단계: 서버 권한 영웅·최종 대전과 예약 공개

- `hero_reward_tokens` 원장은 달성 ID별 추첨을 멱등 처리하고 팀·시즌 내 같은 영웅 중복을 막는다. 등급 60%·30%·10%와 소진 등급 재분배는 서버 함수가 적용한다.
- 기존 로컬 영웅은 첫 연결 때 서버 원장으로 가져오되, 이미 서버 결과가 있으면 서버 결과를 우선한다. 공개는 서버가 정한 미래 시각에 한 번만 확정한다.
- 같은 원정대 QR 자료에는 최신 공개 이벤트 ID·영웅·시작 시각을 넣는다. 접속 중인 학생 화면은 1초마다 확인하고 아직 보지 않은 이벤트를 같은 서버 시각에 전체 화면 연출로 재생한다.
- 최종 대전 계산식을 `battleAuthority` 순수 모듈로 분리해 브라우저와 Edge Function이 같은 공식을 사용한다. Edge Function은 브라우저가 보낸 피해량을 받지 않고 입력으로 피해량·순위·동률 승점·협동 마무리·이벤트를 다시 만든다.
- 서버는 공식 경기 수와 영웅 원장의 팀별 보유 목록을 대조하고 시즌별 결과 하나만 `final_battles`에 저장한다. 같은 요청은 저장된 결과를 돌려주고 다른 입력으로 재계산하지 않는다.
- 서버가 연결되지 않은 로컬 개발·체험 흐름은 기존 계산과 공개를 유지한다. 실제 수업 서버에서는 새 마이그레이션과 `game-authority` Edge Function 배포가 필요하다.

## 구현 완료된 주요 기능

- 교사 원정 관리: 명단·편성·도전점퍼, 공식 경기 기록 확정 및 취소(서버 감사 원장), 훈장 생성 및 수여(+10P), 시즌 종료 및 최종 대전 계산
- 학생 원정대 게시판:
  - 학생 가입 없이 QR/링크 접속
  - 전체 원정대 및 대원 열람
  - 학생별 훈장과 성장 기록 확인
  - 현재 보유 포인트 확인
  - 병력 카드 및 비밀 힌트 서버 구매 (Supabase 트랜잭션)
  - 보유 병력 및 공개 영웅 확인
  - 새 영웅 알림 및 봉인 영웅 학생 직접 개봉
