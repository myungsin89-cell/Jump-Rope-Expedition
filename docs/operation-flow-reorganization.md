# 줄넘기 원정대 · 운영 구조 정리와 개발 순서

> 갱신일: 2026-10-20  
> 상태: 현황·명단·시즌·연습 기록 개편 및 로컬 훈장 수여 연결. 공식 보상은 후속 단계
> 목표: 들어오면 현황이 보이고, 기록 버튼을 누르면 바로 기록한다.

실제 구현과 검증 결과는 `operation-screen-implementation.md`를 참고한다. 아래 내용에는 이미 구현한 화면과 아직 남은 보상 기능의 목표가 함께 있다.

후속 사용자 결정 D-023에 따라 디자인 개편은 보류하고 로컬 기능을 먼저 완성한다. 로컬 훈장은 `local-feature-progress.md` 참조. 아래 서버 트랜잭션 기준은 공식 운영 연결 시 적용하며, 현재 브라우저 연습 저장소를 공식 보상으로 취급하지 않는다.

## 1. 화면은 세 개만

**원정 시작하기 → 원정 목록 → 원정 선택 → 현황판**

- 시작 버튼 뒤의 `새 원정 / 이어가기` 선택창은 없앤다.
- 목록에서 기존 원정을 카드로 보여 주고 `원정 만들기` 버튼을 제공한다.
- 등록된 원정이 없어도 같은 목록 화면에서 생성한다.
- 원정에 들어가면 설정 화면이 아니라 **현황판**을 기본으로 연다.
- 원정 안의 상위 메뉴는 **현황 · 명단 · 시즌 설정** 세 개뿐이다.
- 경기 기록은 네 번째 메뉴가 아니라 현황판의 큰 **경기 기록하기** 버튼으로 연다.
- 다른 원정으로 돌아가는 위치를 화면마다 일정하게 둔다.

## 2. 이름을 구분한다

| 구분           | 화면 이름 | 의미                                                        |
| -------------- | --------- | ----------------------------------------------------------- |
| 전체 운영 묶음 | 원정      | 최대 5개 시즌과 학생·원정대를 묶는 단위                     |
| 기존 팀        | 원정대    | 학생들이 이름을 정하는 2~4개 팀                             |
| 대표 학생      | 원정대장  | 해당 원정대 소속 학생 중 지정                               |
| 팀원           | 원정대원  | 해당 원정대 소속 학생                                       |
| 기존 메달      | 훈장      | 교사가 학생에게 수여하는 개인 기록, 수여당 소속 원정대 +10P |

앱 제목은 `줄넘기 원정대`로 유지한다. 화면의 `학급 생성/학급 목록`은 `원정 만들기/원정 목록`으로 바꾼다. 전체 묶음과 개별 팀을 모두 원정대라고 부르지 않는다.

전체 원정에 별도 작명을 강제하는 단계를 추가하지 않는다. 기존에 저장한 학급 표시 이름·학생·기록도 없애지 않는다. 내부 `expeditions`, `teams`, `medal_*` 식별자나 저장 키는 화면 용어를 바꾸는 이유만으로 일괄 변경하지 않는다.

## 3. 현황판: 운영에 필요한 내용을 먼저

### 위에서 아래 순서

1. 현재 시즌, 기간, 운영 상태, 기록한 경기 수
2. **경기 기록하기** 버튼
3. 원정대별 구성과 순위·포인트
4. 최근 경기 기록과 결과
5. 결과가 있는 경우 최종 대전 누적 승점·누적 피해량·전체 순위

### 원정대별 표시

- 원정대 이름, 깃발·색상 등 구분 요소
- 원정대장
- 원정대원 이름들
- 도전점퍼와 개인별 배수
- 최근 경기 순위와 현재 사용 가능한 포인트
- 학생 이름 옆의 작은 훈장 이미지

원정대별로 단정한 구역을 만들고 학생 이름을 촘촘하게 배치한다. 학생 한 명마다 큰 카드를 만들지 않는다. 색만으로 원정대를 구분하지 않고 이름도 항상 보여 준다.

**최근 경기 순위 / 최종 대전 누적 승점 / 현재 포인트 잔액**은 서로 다른 값이다. 포인트 잔액을 전체 순위처럼 표시하지 않는다.

이 현황판은 교사용 운영 화면이다. 학생에게 공유하는 화면에서는 다른 원정대의 잔액·병력·힌트·영웅 상세를 숨기는 기존 규칙을 유지한다. 교사용 현황판을 그대로 학생 QR 화면으로 재사용하지 않는다.

### 아직 준비가 안 됐다면

현황판은 항상 들어갈 수 있게 한다. 기록 버튼을 누를 때 필요한 항목만 확인한다. 부족하면 `원정대원을 배정해 주세요`처럼 이유와 해당 메뉴로 가는 동작을 함께 보여 준다. 확인 버튼을 여러 번 눌렀는지로 진입을 막지 않는다.

## 4. 명단: 학생 관련 작업을 한곳에

학생 30명 안팎을 기준으로 **한 학생당 한 줄**로 구성한다.

`번호 · 이름 · 소속 원정대 · 원정대장 여부 · 도전점퍼 여부 · 배수`

- 학생 추가 버튼 → 모달에서 한 명 또는 여러 명 등록
- 이름 수정은 해당 학생을 선택했을 때만 편집
- 원정대 수는 2·3·4개 중 설정
- 원정대 이름, 대장 지정, 대원 배정, 도전점퍼와 배수를 이 메뉴에서 처리
- 도전점퍼는 원정대별 1~2명, 개인별 1~3배 유지
- 추가 입력창·큰 이름 편집칸을 기본 목록에 상시 펼쳐 두지 않음
- 기존 학생 ID를 유지하여 이름 수정·팀 이동 후에도 개인 이력이 연결되게 함

상위에 `팀 편성`, `도전점퍼` 메뉴를 다시 만들지 않는다. 명단 안에서도 큰 설정 마법사를 새로 만들지 않는다.

원정대장은 먼저 대표 학생 표시 역할로 다루는 것을 권장한다. 전용 로그인·구매 독점 권한은 합의하지 않았으므로 추가하지 않는다. 대장 필수 여부 등 미확정 항목 때문에 현재 기록판을 임의로 막지 않는다.

## 5. 훈장: 평소에도 수여하고 원정대에 자동 +10P

### 확정한 운영 방식

- 교사가 경기 외의 일상생활 중에도 학생에게 줄 수 있다.
- 특정 경기 선택이나 경기 기록 생성이 수여의 선행 조건이 아니다.
- 훈장 1개 수여 시 학생의 수여 당시 소속 원정대에 **10P가 자동 지급**된다. 개인이 쓰는 포인트를 따로 만들지 않는다.
- 기존 `학생당 경기별 최대 1개` 제한은 경기 독립 수여 방식에 맞춰 폐기한다. 임의의 일일 한도를 새로 넣지 않는다.
- 경기 포인트 계산과 훈장 포인트를 분리하여 경기 저장·재계산 때 훈장 10P가 다시 더해지지 않게 한다.
- 종류와 관계없이 10P 고정. 교사가 훈장마다 지급 포인트를 바꾸는 옵션은 만들지 않는다.
- 시즌이 바뀌어도 훈장 종류와 학생 수여 이력은 유지한다. 포인트는 기존처럼 시즌 한정이며 이월하지 않는다.

### 만들기와 주기

- 명단 상단의 **훈장 만들기·수여** → 완성형 훈장 모양에 이름·설명·색상만 정한다.
- 기본 훈장 종류는 제공하지 않는다.
- 사용한 훈장 정의는 삭제하지 않고 사용 중지한다. 과거 수여 이력은 유지한다.
- 같은 훈장 창에서 학생을 골라 바로 수여하거나, 명단 또는 현황판에서 학생 클릭 → 훈장 카드를 한 번 눌러 수여한다.
- 훈장 선택·수여 시 `소속 원정대 +10P`를 명확히 보여 준다.
- 학생 상세창에서는 훈장 이미지·이름·설명·수여 날짜·횟수를 확인한다. 경기 연결을 필수로 표시하지 않는다.

### 현황판 표시

- 학생 이름 옆에는 작은 **훈장 이미지만** 표시한다. 이름·설명·횟수를 매번 나열하지 않는다.
- 같은 종류의 훈장은 아이콘 하나로 묶고, 전체 이력과 횟수는 학생 상세창에서 보는 방식을 적용한다.
- 이미지만 보이더라도 보조기술에는 훈장의 의미를 전달한다.
- 훈장 수여 후 해당 학생의 아이콘, 소속 원정대 포인트, 관련 영웅 임무 진행도가 갱신된다.

### 보상 저장에 필요한 구현 원칙

- 수여 이벤트마다 고유 ID, 학생 ID, 훈장 ID, 수여 당시 원정대 ID, 귀속 시즌, 교사, 시각을 기록한다. 경기 ID는 필수가 아니다.
- 한 수여 이벤트의 훈장 기록과 +10P 장부 반영은 서버에서 함께 성공하거나 함께 실패해야 한다.
- 중복 클릭·요청 재시도는 같은 수여를 두 번 지급하지 않도록 처리한다. 교사가 의도적으로 다시 수여한 별개 이벤트와는 구분한다.
- 영웅 임무 `빛나는 동료들`은 포인트 장부가 아니라 서로 다른 실제 훈장 수상 학생을 기준으로 판정한다.
- 학생이 이동해도 훈장 개인 이력은 학생을 따라가고, 이미 지급된 원정대 포인트를 새 원정대로 옮기지 않는다.
- 읽을 수 없는 원본, 기존 연습 기록, 기존 저장 키를 초기화하거나 덮어써 해결하지 않는다.

## 6. 시즌 설정: 이번 시즌만 준비

- 처음에는 1시즌만 준비하고 필요할 때 최대 5시즌까지 추가한다.
- 이번 시즌의 기간과 비밀 보스를 교사가 정한다.
- 미래 시즌이 미작성이어도 준비된 현재 시즌의 기록은 가능하다.
- 경기 시간·총 경기 수를 앱이 정하지 않는다.
- 종료 예정일에 자동 종료하지 않는다. 기존 교사 수동 종료·최종 대전 흐름을 유지한다.
- 원정대 수를 바꾼다고 병력 가격·기본 포인트·보스 정보를 임의 변경하지 않는다.

## 7. 영웅 임무에서 확정한 변경

| 임무                                 | 정리한 기준                                                                                                               |
| ------------------------------------ | ------------------------------------------------------------------------------------------------------------------------- |
| 빛나는 동료들                        | 서로 다른 훈장 수상자 누적 4명·8명·12명…마다 달성. 시즌과 관계없이 누적하며 같은 학생의 반복 수상은 새 인원으로 세지 않음 |
| 꾸준한 발걸음                        | 2팀 운영에서는 발동하지 않음. 3~4팀 운영의 기존 기준은 4경기 연속 2위 이상                                                |
| 다시 일어선 원정대                   | 2팀 운영에서는 발동하지 않음. 4팀의 출발 순위 표기는 아래 미정 항목에서 확인 필요                                         |
| 다섯 계단 · 빛나는 도전 · 네 가지 힘 | 2팀이라는 이유로 비활성화하지 않음                                                                                        |

훈장을 경기 밖에서 줘도 빛나는 동료들의 수상자 누적에는 포함한다. 한 학생에게 여러 번 준 훈장은 각각 +10P이지만, 서로 다른 수상자 수에서는 한 명이다.

## 8. 아직 정하지 않은 것: 임의로 구현하지 않음

| 항목                      | 남은 결정                                                                                                                                           |
| ------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------- |
| 4위 순위 보너스           | 기존 1위 30P·2위 20P·3위 10P는 유지. 4위 값은 미정                                                                                                  |
| 4팀의 다시 일어선 원정대  | 원래 의도는 꼴찌 → 다음 경기 1위. 기존 문서는 3위 → 1위로 고정되어 있어 4팀에서 4위 → 1위로 일반화하는 문구를 최종 확인해야 함                      |
| 진행 중 원정대 수 변경    | 이미 쌓인 순위·성장·승점·영웅 진행도와 원정대 정체성을 어떻게 보존할지 미정. 임의 병합·초기화 금지                                                  |
| 시즌 진행 전·종료 후 훈장 | 훈장을 줄 수 있다는 원칙과 별개로, 귀속할 진행 중 시즌이 없을 때 자동 10P를 어느 시즌에 반영할지 미정. 포인트 이월·보류 정책을 임의로 추가하지 않음 |
| 원정대 미배정 학생의 훈장 | 소속 원정대가 없을 때의 수여·포인트 귀속 처리 미정. 임의의 다른 원정대에 지급하지 않음                                                              |

미정 항목을 모두 한꺼번에 질문하지 않는다. 먼저 진입·현황·명단의 확정된 구조를 정리하고, 해당 기능의 실제 구현 전에 필요한 결정만 하나씩 확인한다.

## 9. 실제 개발 순서

| 순서 | 작업                   | 확인할 결과                                                                                |
| ---- | ---------------------- | ------------------------------------------------------------------------------------------ |
| 1    | 시작 버튼과 원정 목록  | 시작 버튼을 누르면 바로 기존 원정이 보임. 없으면 같은 화면에서 생성                        |
| 2    | 교사용 현황판          | 원정 선택 직후 시즌·기간·구성원·순위·포인트를 이해할 수 있음                               |
| 3    | 명단 통합              | 30명을 작은 행으로 관리. 학생 추가 모달, 원정대 이름·대장·편성·도전점퍼를 한 메뉴에서 처리 |
| 4    | 시즌·기록 동선 연결    | 현황판의 기록 버튼에서 현재 시즌 개수 입력으로 바로 이동하고 결과 후 현황으로 복귀         |
| 5    | 독립 훈장 수여         | 커스텀 훈장과 일상 수여, 중복 없는 자동 +10P, 아이콘·상세·영웅 진행도 연결                 |
| 6    | 2~4팀 규칙과 회귀 검증 | 미정 규칙 확인 후 팀 수에 따른 계산·표시·원본 보존을 검증                                  |

화면 배열부터 단순하게 만든다. 실제 보상은 인증·서버 장부와 분리할 수 없으므로 로컬 예상값을 공식 포인트처럼 표시하지 않는다. 현황에 보여 줄 데이터가 아직 없으면 샘플 숫자로 채우지 말고 `기록 없음` 또는 연결 상태를 분명히 표시한다.

다른 에이전트의 병력·영웅 카드 작업과 오디오 작업은 보존한다. 1차 화면 개편은 구현했으며, 기존 저장 데이터와 원본 에셋은 보존했다. 공식 보상 연결 여부는 구현 결과 문서에서 구분한다.

## 10. 개편 완료 기준

- 원정 시작하기 뒤에 새로 시작/이어가기 선택창이 없음
- 기존 원정 목록에서 한 번 선택하면 현황판이 열림
- 상위 메뉴가 현황·명단·시즌 설정 세 개뿐임
- 현재 시즌·기간과 원정대별 이름·대장·대원·도전점퍼가 한눈에 보임
- 30명 명단에서 학생 하나가 큰 카드 공간을 차지하지 않음
- 학생 추가 입력은 버튼으로 여는 모달에만 있음
- 기록 버튼에서 불필요한 준비 단계를 반복하지 않음
- 훈장 수여가 경기 선택을 요구하지 않고, 한 수여당 +10P를 한 번만 반영함
- 현황의 훈장 이미지를 포함한 학생을 선택하면 상세 이력을 확인할 수 있음
- 순위·잔액·승점을 혼동하지 않음
- 기존 학생 ID·저장 명단·연습 입력·기록 이력을 보존함
- 새로고침·뒤로 가기·모바일 화면을 실제 운영 동선으로 검증함
